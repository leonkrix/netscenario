# D-074: A set of runs has its own seeds, a named list of metrics, an expanded percentile interval for the mean, and ends with the first failure

Accepted (2026-11-02). Refines D-042 (repetitions as an option of a run, the percentile bootstrap, at least 5 runs). Closes ASR-02 and ASR-03 for the library and the command line.

- **The set is a directory.** `run --repetitions n` writes `run-001` to `run-<n>` (each a whole run, as in D-027) and `runset.json` ([STATISTICS.md](../STATISTICS.md)). Run `i` (from 0) gets the seed `derive_repetition_seed(set seed, i)`, pinned like the seeds of the links. The seed of the set is the one of the scenario (or `--seed`); without one the set draws one and records it, so `--seed` repeats the set. The runs are one after the other: they share the machine, and a run beside another would measure the other.
- **Fewer than 5 and more than 1,000 repetitions are refused before the first run.** Five is D-042. The upper bound is there because a run takes seconds and writes files; a thousand points of a sweep are not repetitions.
- **The names of the metrics are one list for the library, the command line, Python and the reports** (`metric_values`): `<workload>.<what>`, in SI units (`media.delay.p99` in seconds, `media.loss_ratio` from 0 to 1, `media.throughput.mean` in bit/s), and `<program>.<metric>.last|min|max` for the metrics of a program of your own. A metric that only some runs have (the delay of a run in which nothing arrived) gets no interval and is listed under `partial`: an interval from the runs that happen to have it would be a made-up number.
- **The interval of the mean is the expanded percentile interval** (Hesterberg, 2015), not the plain percentile one of D-042. The coverage was measured, 20,000 intervals for each case: the plain interval of the mean of an exponential distribution holds the true value 78 % of the time for 5 runs and 90 % for 20, against the 95 % it claims. The expanded interval moves the ends outwards by the factor that makes the bootstrap interval as wide as the classical t interval for normal data (86 % and 92 % in the same cases, 95 % for a uniform distribution from 10 runs). It needs no other source of random numbers. The median keeps the plain interval, whose coverage is 93 to 94 % for the same data. `--statistic mean|median` chooses (the maintainer's choice, 2026-11-02). The numbers, and what the interval does not promise, are in [STATISTICS.md](../STATISTICS.md).
- **The random numbers are the ones of the schedules** (`xoshiro256++`, written out, D-071), seeded from the seed of the set and the name of the metric (FNV-1a of the name, pinned), so the interval of a metric does not change when another metric appears. The `t` quantile and the normal tail are written out as well (`special.rs`, checked against the published tables).
- **A set ends with the first failure.** A failed run, a cancel (Ctrl-C) or a run that was cut short ends the set with that error and no `runset.json`; the finished runs stay (the maintainer's choice, 2026-11-02). An interval from fewer runs than were asked for, or from the runs that did not fail, would be a silent approximation, and a failure that depends on the behaviour under test would bias it.
- **`float_roundtrip` of `serde_json` is on.** A number that is written to `runset.json` and read back is the same number to the last bit; without it, a value came back one unit in the last place off, and a set could not be compared with itself.
- **Tested:** the coverage on simulated data with known distributions (bounds of four standard deviations around the measured share, with canaries that the plain interval, a point and an interval of half the level fail), the width against the number of runs, the same seed and another seed, the refusals, the tail worked out by hand from the tables, the pinned seeds and a pinned interval; the order of the runs, the seeds and directories, a failing and a cancelled set, with a runner that plays the runs; in real namespaces the set of a lossy scenario (the seeds of the runs, differing runs, the same seed giving the same set).

Alternatives: the plain percentile interval (above: too narrow for few runs); the BCa interval (more code, the inverse normal and a jackknife, and no better at 5 runs); a Student interval (assumes a normal distribution, which delays are not); continuing after a failed run and counting the failures (a biased interval); running the repetitions in parallel (they would disturb each other's timing).
