# D-056: A stream without the checksum of UDP is a raw socket, a boolean and a CRC-32

Accepted (2026-11-01). It settles the open point of D-055 (how the sender switches the checksum off) and revises the spelling of the option in D-040 (`off` became `false`); the formats are version 0, so that is allowed.

- **The sender is a raw IPv4 socket.** `udp-checksum: false` makes the agent open `socket(AF_INET, SOCK_RAW, IPPROTO_UDP)` and write the 8 bytes of the header of UDP itself, with the checksum field 0, which IPv4 allows; the kernel adds the header of IP and picks the route and the source address. It is safe code (`rustix`), and it was tried first in a network namespace with Python. *The cheaper route* was one `setsockopt(SO_NO_CHECK)` in an `unsafe` block, which needs no capability; it was not taken because the workspace forbids `unsafe` (D-025) and the agent reads every packet of every run, so the rule is worth more there than a line is. The price is paid in three places: the capability `CAP_NET_RAW` in the node (a user namespace and root have it; a process with only the two ambient capabilities of [PERMISSIONS.md](../PERMISSIONS.md) does not), the header of UDP written by hand (source port from 49152 on, length, checksum 0; a test pins the receiver, the namespace tests run the sender), and IPv4 only (which is no loss: IPv6 requires the checksum).
- **The missing capability is found before the run, not in the middle of it.** `doctor` has a step `raw-socket` that reads the effective capabilities of the probe's shell in the namespace a run would use (the same set the agent gets), and `check_values` of the Kernel backend refuses a workload with `udp-checksum: false` where it is missing, with the feature `UdpWithoutChecksum` (a new row of [COVERAGE.md](../COVERAGE.md): Kernel 0.2, Engine 0.4, Proxy no: a proxy sends its own datagrams with a checksum of its own). If the probe cannot run, the sender finds out and its error names the capability.
- **The value is a boolean, not `on` and `off`.** YAML 1.1 reads `on` and `off` as booleans (PyYAML, `yamllint`, some editors) and YAML 1.2 as text; the reader of this project took `off` as `false` when it read a file into an untyped value, while a typed field wanted text, so the JSON Schema check of an editor and the model could disagree about one file. `true` and `false` mean one thing in both. The reader still accepts the YAML 1.1 words for a boolean because that is what the YAML library does for a boolean field; the schema and every document say `false`. In Rust the type is `UdpChecksum { On, Off }`, a boolean in the file.
- **Wire format version 2.** A header of 20 bytes: the 16 of version 1 with the version byte 2, then a CRC-32 over every other byte of the payload, zeros at the end included. Version 1 stays as it is and is what a stream with the checksum on sends. The CRC-32 is the IEEE one (Ethernet, zlib, PNG), written by hand (about 80 lines, "slicing by 8" so that a packet of 1,472 bytes takes well under a microsecond), because a dependency that sees every packet is code to trust and this is shorter to check than to audit. It is tested against the published check value, against a bit-by-bit version for every length from 0 to 2,000, against `zlib.crc32` for the exact bytes of a packet, and every single flipped bit of packets of three sizes must be found. Not taken: a CRC in every packet (it measures something that never happens with the checksum on, D-040), a lighter sum (a CRC-32 finds every single bit and every burst up to 32 bits, by construction).
- **What `corrupted` means.** The receiver of such a stream reads only version 2; a datagram that is not a good packet is counted as `corrupted` and is not recorded. It cannot be called `foreign`, because the bit may have been flipped in the magic or the version, so `foreign` is 0 there. A damaged packet is not recorded because its sequence number or send time may be the damaged part, and a record with a wrong sequence number would put a packet that was never sent into the delays and the loss runs; naming the packets is the job of the tap of D-057. It is **in `lost`** (`received` counts intact packets), so `lost - corrupted` is what never arrived, and the loss that a test asserts on is the same as with the checksum on, where the kernel drops the packet. `delivered` of the tally counts it, so the node is not blamed for dropping it. Not taken: counting it as received (it is not the packet that was sent), and as lost without saying (the tool exists to say what happened to each packet).
- **What the CRC does not see, and the shares that follow.** The CRC covers the payload; the kernel catches a flipped bit in the headers of IP (the checksum of IP), Ethernet (the destination address, the type) and UDP (the destination port, the checksum field that is no longer 0, a longer length). Harmless are the source address of Ethernet (6 bytes, as before) and the source port of UDP (2 bytes), which arrive intact, and a shorter length trims the datagram, which the CRC finds. With a frame of `payload + 42` bytes and `k` the number of set bits in the two length bytes (2, 3 and 5 for 64, 200 and 1,200 bytes): packets that arrive damaged = `p x (payload + k/8) / frame` (6.06, 8.28 and 9.67 % for `p` = 10 %), dropped by the node = `p x (34 - k/8) / frame` (3.18, 1.39 and 0.27 %), lost = `p x (frame - 8) / frame` (9.25, 9.67 and 9.94 %). These come from the mechanism, not from a measurement; the first run of the cases on the development machine gave 5.90, 8.37 and 9.59 % damaged and 3.21, 1.26 and 0.29 % dropped, inside four standard deviations in every case ([FIDELITY.md](../FIDELITY.md)). The spike S12 had measured 6.0, 8.2 and 9.6 % damaged with `SO_NO_CHECK`, so the raw socket behaves like the socket option.
- **Breaking changes, and why they are now.** `UdpCbr` is `#[non_exhaustive]` and gains the field `udp_checksum` (a `feat!` for the model crate; `UdpCbr::new` builds one), `Feature` gains `UdpWithoutChecksum`, the result gains `corrupted` and the agent's `received` line gains `corrupted` (both with a default, so older files are read). The model has no users outside this repository yet, and `non_exhaustive` is what lets later keys (the next ones are planned) arrive without another break.

Alternatives: an `unsafe` block for `SO_NO_CHECK` (above); `udp-checksum: off` as a word (the YAML 1.1 problem above); a CRC only in the first bytes (the point is the whole payload); recording the damaged packets with a flag (above).
