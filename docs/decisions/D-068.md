# D-068: What the kernel refuses is not declared, and a run follows the same probe as `doctor`

Accepted (2026-11-02). It closes the last open point about the declaration of the Kernel backend (BKD-03, D-013, D-052): `capabilities()` followed the version of `tc` only, so a machine whose kernel has no `sch_netem`, whose `tc` finds no table for the normal distribution or whose kernel refuses a model was declared `Exact`, and the run found out after the network was up, with an error of `tc` and the exit code 3. `doctor` showed it, the run did not use it.

- **One probe, cached, for the way the run takes.** `doctor::PROBE` already tried every thing a scenario can need in a throwaway namespace (the pair, `netem`, the tables, the seed, the five models, the duplicating tree, `CAP_NET_RAW`). `KernelBackend` runs it once, the first time the declaration or a value is asked for (about 15 ms; `OnceLock`), in the way the run takes (`own_rights` or a user namespace). Before, the probe was run again for each question (the tree, the raw socket); now they read the same steps.
- **`capabilities_probed(environment, probed)`.** The version of `tc` gives the declaration as before (`capabilities` is that, with a `Probed` that knows nothing), and the probe takes away what the kernel refuses: `netem` refused is every feature that needs it and the seeded loss; the models (`burst` and `chain`, `reorder`, `duplicate`, `corrupt`) are the features of the same name, one each; a seed that `tc` of a recent version does not accept is `SeededLoss` refused (an old `tc` keeps the reason of its version); no pair is `PointToPoint` refused. Each refusal has the answer of the machine as its reason and a fix. The steps after a failed pair say nothing about `tc` (`doctor` already said so).
- **The normal distribution is a value, not a feature.** `Jitter` covers the uniform and the normal one, and the uniform one works without tables, so refusing the feature would refuse a scenario that runs. `check_values` refuses the jitters with `distribution: normal`, in a link and in a step of the timeline, when the probe could not find the table, with the path, the line of the file and, if `TC_LIB_DIR` is set, the directory in the fix. Measured with `TC_LIB_DIR=/nonexistent`: before, the run built the network and failed with "No distribution data for normal"; now `netscenario run` exits with 2 at once, and the uniform jitter runs on the same machine.
- **`doctor` and a run say the same thing.** The feature lines of `doctor` are made from the same function and the steps of the first way that works, so a refused model is a `warn` on its line.
- **When the probe cannot run** nothing is known and the declaration follows the version, as before. This is the case where a run finds out for itself.
- **API.** `Probed` and `capabilities_probed` are new; `capabilities` and `Environment` are as they were.
- **Tested.** The declaration with synthetic probes: nothing wrong or nothing known changes nothing; each refused step refuses exactly its feature and no other; no pair is not blamed on `netem`; a seed that an old `tc` does not know keeps the reason of the version. The doctor: a refused reorder is a warning on its line. The value: a normal jitter in a link and in a step is refused with the path and the directory, a uniform one asks nothing, a table that is there says nothing. The program, with `TC_LIB_DIR` pointing nowhere: exit 2, the line of the file, the way out, no result, and a uniform jitter runs.

Alternatives: the probe at `KernelBackend::new` (every backend would pay it, also one that only reads the result or asks the version); the declaration of `Jitter` as `Limited` without tables (a limited feature is refused until it is accepted, and the uniform jitter would go with it); making `doctor` itself the gate (a run would need a report to read, and the report is for people).
