# D-085: A trace is replayed by its moments and its sizes, read from a CSV file or a capture when the scenario is loaded

Accepted (2026-11-04). Release 0.3 adds the workload `trace-replay` (WRK-03). D-083 says how the file reaches the scenario.

- **The trace is moments and sizes, packet by packet.** Packet `n` leaves at the `n`th moment (from the start of the workload) with the `n`th payload. The sender walks it like any schedule (D-071): the moments are a function of the trace, the series and the barriers of the timeline get them by walking it again, and a window cuts it. Packets at the same moment are sent one after the other.
- **The sizes are not in the records.** A receiver records the sequence number and two times, as before. The size of an arrived packet is the size of its sequence number in the trace, which the run knows, so the format of the records and the receiver do not change. What counts bytes (the throughput of a bin, the series, `received_bytes`) takes the size by sequence number from the schedule.
- **CSV: `time,size`, each with its unit.** `12.5ms,1200b`, like every value of the format; a number without a unit is refused with its line. A size below the smallest payload (the header of the agent: 16 bytes, 20 without the checksum) is refused, because the writer of a CSV file meant it.
- **Capture: one flow, the transport payload, raised where it must.** A `pcap` or `pcapng` file is read for the packets of one flow (UDP or TCP over IPv4 or IPv6, by `select` or the only one), with the transport payload as size and the time of the capture as moment. A TCP acknowledgement has no data and cannot carry the header of the agent: it is raised to the smallest payload, and the trace says how many (`padded`) and the result repeats it. The alternative (leave them out) would change the rate of the flow; refusing the capture would refuse nearly every real one.
- **The trace is expanded into the scenario.** The packets are packed as LEB128 numbers (the time since the packet before, the size) in hexadecimal, with the SHA-256 of the file: about 10 characters for a packet, 100,000 packets at most. The limit of a scenario file is 4 MiB for that reason.
- **Frames are counted for each packet.** A packet that is cut by the MTU of the first link makes more frames than one that is not (D-081); the frames of a flow are the sum over the packets that were sent, less the ones the kernel refused. The tally by packet is not kept where a packet is cut, as before.
- **The agent reads a file.** The run writes the trace as text for the agent (`flow-<n>.trace`, `docs/AGENT.md`); a trace of 100,000 packets does not fit a command line.

Alternatives: times only and one size (the first plan; a trace without its sizes is half a trace); the size in the record of every packet (a new version of the file for a number the run knows); leaving the acknowledgements out of a capture (the rate of the flow changes without a word); the path of the file at the run (D-083).
