# D-080: A packet is accounted for link by link along its path, by the counts of the nodes, where the run can tell which packets enter a link

Accepted (2026-11-04). With networks of several nodes (D-078) a packet crosses several queues, and the account of D-040 (lost in the queue, dropped by the node, delivered) and the check of the queues for the seed (ENV-07, D-036) had to follow it.

- **What enters a link.** On the first link of a path it is what the workloads put in. On a later link it is what arrived at the node before it: the frames that the receiving interface of each earlier link counted (`/proc/net/dev`, before and after the workloads), because a router forwards every packet it takes and makes none. This is exact when every workload that crosses an earlier link of this kind goes on into this link; the run checks that on the paths and says nothing otherwise.
- **Where it cannot be told, there is no tally and no check.** If frames that arrived at a node are for two links (two workloads part at a router) or the packets may take one of several routes (ECMP), the run does not know which of them enter a link, and the entry is left out. The packets are still measured end to end.
- **The tally of a link that ends at a router** has `delivered = reached_node`: a router takes what arrives, and what it does with the packet shows on the next link. `lost_in_queue` is `null` after a link that corrupts, because a router drops a packet whose header was damaged, and that packet arrived at the node but did not enter the next queue.
- **Reproducibility.** The queue of a later link is held to the packets that arrived at the node before it, so a chain with one workload and a seeded loss on any link stays reproducible. It is not reproducible, and the result says why, when two workloads reach a queue (the order is not fixed), when an earlier link of the path can reorder packets (a jitter or a reorder, so the packet that draws a number depends on the timing), or when the run cannot tell which packets enter it.
- Alternatives: a counter for every flow in every node (an `nftables` rule or a `tc` filter for each flow and link; exact for every network, but more machinery in every node and a changed packet path, and a counter that is itself a part of what is measured); declaring every path of more than one link not reproducible (what the first version did, and a limit that has a correct solution).
