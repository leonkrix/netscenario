# D-078: A topology is one graph with shortcuts, the routes are automatic, set in part or fully manual, and every node has an address of its own

Accepted (2026-11-03). Release 0.3 turns the point to point link of releases 0.1 and 0.2 into networks of several nodes, several paths and several senders and receivers (TOP-02 to TOP-06, TOP-08). The experiments that decide the build of the Kernel backend are in D-079; this record is about what a scenario says and what the tool does by itself.

- **One canonical form: nodes and links.** A node is a `host` or a `router` (only a router forwards). A link joins two nodes and has the impairments of each direction as before; two nodes may have several links (multipath, multi-homing). The scenario file, the Rust builder and the Python builder all write this form, and its hash is the identity of a scenario (replay, result).
- **Shortcuts for the common shapes.** `star`, `chain`, `dumbbell` and a pair of paths are written in a few lines and expanded when the file is read. A shortcut and its long form have the same canonical form and hash. `netscenario expand` prints the long form, so a user moves from the easy form to the manual one by reading it.
- **Routing has three levels, not one.** `routing: auto` (the default) computes a route for every node to every node by the shortest path (hop count; a link may have a `cost`; ties are broken by the order of the links, so the result is deterministic; ECMP and weights only when asked). The routes of a node (`routes`) add to the automatic ones or replace single entries. `routing: manual` switches the automatic routes off, and only the given ones count. Fixed routes and a fully manual network are as much part of the design as the automatic case (asked by the maintainer).
- **No routing protocol is built in.** A routing daemon (FRR, BIRD, babeld) runs as a program of a router node (WRK-06) and the timeline moves the network under it (`down`, `up`, outages). The time until traffic flows again after an event is measured by the recovery of release 0.2.
- **Every node has an address of its own on `lo`** (/32 and /128). A workload and a program name a node (`{server.addr}`) and not an interface, so a multi-homed node needs no choice of address and the path is whatever the routing says. The links get /30 and /126 subnets; the addresses are assigned by the tool and recorded in the result. The first hop of a multi-homed host can be chosen with `from: { node, via: link }`; pinning one flow to a path over several nodes (policy routing by the source address of the workload) is not part of 0.3.
- **IPv6 is a property of a scenario** (`ip: v4 | v6 | dual`, default `v4`). The namespaces stay quiet: no duplicate address detection, no router advertisements, fixed neighbours, and the queues are installed after the counters of all interfaces have stood still (an IPv6 interface sends about 8 packets in its first half second and nothing later, measured on both runner images). A kernel without IPv6 is found by a probe and refused with a message that names it.
- **Failover is routing and the timeline.** When a link of the first path goes down at the interface of the sending node, the second path takes over at once; when only the far end goes down the sender's route stays and everything is lost, unless `ignore_routes_with_linkdown=1`. So `down` takes down the node-side interface (the sender gets `Network is unreachable`, as in release 0.2) and the sysctl is set on every interface of a node with more than one route (measured, both images).
- **What a reader sees.** The result has the topology, the addresses, the effective routes (automatic plus given) and the path of each workload; the HTML report draws the graph; `netscenario show` prints the graph and the routes as text or Graphviz.
- **A limit and an honest scope.** A scenario of more than 64 nodes is refused with a message that names the override; building a node takes 100 to 250 ms and a larger network shares the processors of one machine, so the timing degrades with the size and the doctor says by how much. The tool is a laboratory for the conditions of a path and for measuring a program under them, not a network simulator or a testbed of switches, VLANs and wireless media (TOP-09, TOP-11, TOP-12 are ideas), and the documents name other tools for those.

Alternatives: automatic routing only (the common case, but no control), manual routes only (every scenario would list its routes), routing protocols built in (a second product; the faithfulness of each implementation would have to be proven), one address per interface and workloads that choose an interface.
