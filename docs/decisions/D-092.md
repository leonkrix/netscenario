# D-092: A scenario accepts the restrictions of a backend one feature at a time, and the result records them

Accepted (2026-11-06). The rule since release 0.1 is that a backend never approximates silently (ARCHITECTURE.md). Release 0.3 is the first with features that the Kernel backend reproduces only in part (`fast-rate-steps` and `stalled-link`, D-091), so the way out that the rule promised is built.

- **The backend says it.** Its declaration (`Capabilities`) gives each feature `Exact`, `Limited { restriction }` or `Unsupported { reason, fix }`. The restriction is a sentence with the numbers that were measured. A feature that the scenario needs is checked against it before anything is created, on the scenario as the file writes it (a model is judged by its states and rows, a Markov chain by its mean stays, so a seed cannot decide whether a run is allowed).
- **The scenario accepts it by id.** `allow-limited: [fast-rate-steps]` at the top of the file lists the features whose restriction the scenario accepts. A list of ids and not a switch: a restriction that comes with a new feature or a new backend is not accepted by an old file. A feature that is `Limited` and not listed is refused with the line to write (`accept the restriction with allow-limited: [fast-rate-steps] in the scenario`). A feature that is `Unsupported` is refused whatever the list says, and an id that names no feature is an error with a suggestion. The list is part of the scenario, so it is in `scenario.json`, in the hash, and in a replay. Python: `allow_limited=[...]` of the builder.
- **The result records what was accepted.** `accepted_restrictions` has the feature and the restriction text, from the backend, for each restriction that applied to this run (a listed feature the run does not need is not recorded). A report prints them next to the numbers they limit.
- **No command-line switch.** What a scenario accepts is a property of the scenario and of how its numbers may be read, not of one run; a run option would make two runs of one scenario hash differently-limited numbers the same.

Alternatives: a boolean `allow-limited: true` (accepts what is added later without a word); a switch of the command line (the numbers of a run would not say what they are worth); refusing without a way out (the Kernel backend could not run a real trace at all); a warning and a run (a silent approximation with a note that nobody reads).
