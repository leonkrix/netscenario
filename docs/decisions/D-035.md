# D-035: A run takes the way that `doctor` reports: its own rights if it has them and they work, else a user namespace

Accepted. The first version chose by the user id alone (root: own rights, anyone else: a user namespace), while `doctor` probed the rights of the process. A user who is not root but has `CAP_NET_ADMIN` and `CAP_SYS_ADMIN` passed the probe and still failed the run when user namespaces were refused (found while writing the permissions guide; reproduced with an unprivileged process with the two ambient capabilities and `user.max_user_namespaces=0`, which gave "No space left on device").

- **The rule.** The backend decides once, in `KernelBackend::new` (the Python package and the command line both pass through it). A process has rights of its own if its effective user id is 0 or its **ambient** set (`CapAmb` in `/proc/self/status`) holds the two capabilities. Such a process tries the namespaces of a run with its own rights (one `unshare ... true`, a few milliseconds), then in a user namespace, and takes the first that works; if neither works it keeps its own rights, so that the run fails with the answer of `unshare`. A process without rights of its own takes the user namespace without a probe. The result records the choice (`rights`).
- **Why the ambient set.** A run starts `unshare`, which starts the supervisor. A capability that is only permitted or effective (from `setcap` on the file, or from a process that was started with it) is dropped at the first `exec`; only the ambient set survives. `doctor` probes by running the same `unshare`, so it reports the truth, and a process with capabilities on the file is told `own rights` is not available.
- **Root without the rights.** Root in a container without `SYS_ADMIN` used to fail even where a user namespace works. It falls back to the user namespace now, as `doctor` already said.
- **How it is tested.** The decision is a function of the text of `/proc/<pid>/status` and of two probes, with canaries (one capability is not enough, an old kernel without `CapAmb`, the real user id and not the effective one). A test in the CI step that runs as root starts itself as an ordinary user with `setpriv --ambient-caps` and checks the way and that a node can be created; with one capability and with none it must choose the user namespace, and a check with a wrong expectation must fail.

Alternatives: raising the ambient capabilities from the program (needs `unsafe` for `prctl`, which the workspace forbids), a command line option for the way (the user would have to know what `doctor` already knows; `Mode` stays for the library), probing with the whole probe of `doctor` (it also builds a veth pair and three `netem` qdiscs: too much for the start of every run).
