# D-026: A program in a node is read through the supervisor by polling, and its memory is limited with prlimit

Accepted. The agent runs as a program of a node (D-025), so the backend needs more than "start": the output of the agent is its report, its input is how it is told to stop, and its end is a result (BKD-03, WRK-01, SAF-02).

- **Three calls in the interface** (`netscenario-core`): `start_program` (as before, now with `Program::memory_limit`), `poll_program(program, wait)` and `send_line(program, line)`. `poll_program` returns as soon as a program wrote a line or ended, or after `wait` with an empty answer, and gives the new lines, the exit (`Code` or `Signal`), the end of standard error (16 KiB) and a `truncated` mark. Polling and not a callback or a stream, because the supervisor answers one request at a time, the caller waits on one program at a time (a run is sequential: receiver ready, sender ends, receiver stopped), and a blocking call with a timeout is the simplest thing that cannot lose a line.
- **Nothing is lost at the end.** A program is reported as ended only after its standard output and standard error have been read to the end (at most 500 ms of grace for a program that left a process behind that keeps the pipe open). Two tests found that this was first not so: the end of a supervisor and the end of a program were reported before the thread that reads standard error had finished (a flaky hint in an error, and a flaky `stderr` in the state). Both are fixed and run 30 times in a row.
- **The supervisor keeps at most 10,000 lines per program** and says when it dropped some (`truncated`). The agent prints a handful.
- **Memory is limited with `prlimit --as=BYTES`** (util-linux, which the backend needs anyway), as `nsenter ... prlimit --as=N -- program`: `prlimit` sets the limit and becomes the program, so nothing stays in between. A limit on the address space is a limit on what a program can map, not on what it uses, and that is the point: allocating past it fails. Alternatives: cgroups (need rights that the unprivileged mode lacks, as D-022 said), `ulimit` in a shell wrapper (a shell in between, and not every program is started by a shell), `RLIMIT_AS` set by the supervisor on itself (would limit the supervisor too).
- **`prlimit` is a required tool** (`Toolbox`, `doctor`), like `unshare` and `nsenter`.
- **The end-to-end test needs the agent binary** next to the supervisor binary. `just test` and `just test-kernel` build it (the recipe tests both packages); a test that does not find it says so and stops, except on the CI, where it fails.
