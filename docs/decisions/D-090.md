# D-090: Models over time are compiled into the steps of the timeline when a run begins

Accepted (2026-11-06), for the periodic patterns (LMD-05), the Markov models (LMD-04), the repeating events (TML-03) and later the traces (LMD-03).

- **A model is a source of timeline events.** At the start of a run, after the seed is known, the core replaces every model by ordinary events (`set`, `outage`, `down`, `up`) in a copy of the scenario, and everything after that is what exists today: the steps are made by `timeline::steps`, applied before the first packet that a workload sends at or after their moment (D-038, D-062), recorded in `events` of the result, and the same seed gives the same lost packets. A backend needs no new method and a new backend gets models with the timeline. `scenario.json` keeps the model, not the events: with the seed the run can be repeated, and `netscenario expand --seed n` shows the compiled events.
- **Why at the start of a run and not when the file is read.** The seed can be replaced on the command line (`--seed`) and each repetition of a set has its own (D-074); a Markov chain is drawn from it. The compile is a pure function of the scenario, the seed and the length of the run, with the generators of `rng.rs`, in the model crate, so that the reader and the core use one code.
- **A state is a complete overlay on the link as the file writes it.** `forward`, `reverse`, `both` of the link are the base. A state names the keys it changes (`rate`, `delay`, `loss`, ...); entering it, the compiled step sets those keys to the values of the state and every key that the previous state changed and this one does not back to the base value (`null` where the base has none). So a state means the same whatever came before it, which a chain whose order is random needs. Each state is checked once when the file is read, as a direction with the base and that overlay (a `jitter` distribution that differs from the base is refused as for a step, D-059); the compiled sequence is then valid by construction.
- **A state can also be an `outage`** (the whole stay in the state is a window in which nothing leaves the link, D-064) **or `down`** (the interface is down for the stay, and comes up when the state ends). A satellite pass or a duty cycle is a periodic model with such states.
- **Periodic**: a list of states with a duration each, run in order, `repeat` (default: forever until the end of the run) or `once`; the first state begins at 0. The schedule is exact: no draw. **Markov**: states with a mean stay (`fixed` or `exponential`, as in the on/off source, D-071), a row of probabilities to the other states (the sum is 1, none to itself), and the start state, which is written (no draw). It is a semi-Markov chain, whose share of time in a state is `pi_i m_i / sum_j pi_j m_j` with `pi` the stationary distribution of the rows and `m` the mean stays; a test compares the run with that. **Repeating events** (`every`, and `until` or `count`) in the timeline become copies of one event.
- **The draws come from a stream of their own per link**, derived from the seed and the `id` of the link (not its position), so a model on another link, or a new link, does not change this one. The derivation is pinned by a test like the others (seed.rs).
- **The number of steps is bounded**: 10,000 events from the models of one link and 50,000 in all (each is a `tc` change in a namespace, a few milliseconds). A model that would make more is refused at the start of the run with the link, the model, the bound and the mean stay that causes it, not cut short.
- **A link with a model keeps the keys of its states for itself.** A `set` of the timeline on such a link must not name a key that a state of the model writes, and a link whose model has outage or `down` states takes no `outage`, `down` or `up` of the file: the model would undo the change at its next step, and the file would not say what happens. The reader says which key or which state it is. Everything else in the timeline works with a model.
- **Traces (LMD-03)** are a fourth source: a table of `(time, rate, delay, loss)` becomes states and steps by the same compile, with the limit on the resolution of the backend (the restriction `allow-limited` of its own decision).

Alternatives: a state machine in each backend (every backend would repeat the barrier logic and the tests, and the Kernel backend would need a thread that steps by the clock, with no packet-exact moment); expanding the models when the file is read (the seed would be fixed by the file, and repetitions and `--seed` would not change a Markov chain); a state as a difference to the previous one, like a `set` (the state would depend on the order in which a chain visited them).
