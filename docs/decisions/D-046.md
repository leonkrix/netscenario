# D-046: The result types are `non_exhaustive` from release 0.2

Accepted (2026-10-31). Release 0.2 adds to the result (events, programs, series, the reason why a loss is not reproducible), and every such addition breaks the code of a library user who builds the struct (cargo-semver-checks, D-037, finds it; `queue_checks` of release 0.1 already did). The structs that the run returns (and the events) get `#[non_exhaustive]` once, as a breaking change of release 0.2 with `feat!:` in the title; after that a field is an addition. Users of the library read results, they do not build them. **Carried out** in `feat!: mark the result types non-exhaustive`: `RunResult`, `ScenarioInfo`, `SeedInfo`, `QueueCheck`, `AcceptedRestriction`, `AddressInfo`, `Timing`, `SenderInfo`, `WorkloadResult`, `Provenance`, `DelaySummary`, `Throughput` and `FlowStats`. `QueueCheck` gets `QueueCheck::new` because tests of other crates build it; the others are read, deserialized (serde is not affected by the attribute) or taken from a run. The events are different: `RunEvent` was already `non_exhaustive` (a new kind of event is a new variant), but its variants are **not** marked, so that a front end and its tests can build the events they show. A step of the run that needs more data gets a new variant and not a new field of an old one. Alternatives: breaking again with every release (the project's own check would ask for the mark each time); a builder for each type (more code for no reader).
