# D-049: The impairments of release 0.2 in the format

Accepted (2026-11-01), after the measurements of D-048. The format reads them now; the Kernel backend applies them later in release 0.2 (done: D-054, D-055, D-056, D-057) and refuses them until then (a `Feature` each, declared `Unsupported` with the reason "applies this from release 0.2", and the row of the coverage page says `✔ 0.2`).
- **Names are those of `netem`, no aliases.** `loss: { model: gilbert-elliott, p, r, loss-bad, loss-good }` (the third and fourth argument of `gemodel`, D-048), `loss: { model: markov4, p13, p31, p32, p23, p14 }`, `reorder: { share, gap }`, `duplicate: P`, `corrupt: P`. No `correlation` key anywhere.
- **Every parameter of a model is required.** `tc` has defaults for `gemodel` (`1-h`, `1-k`), but a default that the file does not show is a value nobody wrote, and a default can be added later without breaking a file while a required key cannot be taken away. `gap` of `reorder` is optional (1 is the default of `tc` and means no rule).
- **What the reader refuses besides the types:** `reorder` without `delay` (the message of `tc` is a line of kernel text; ours names the key), a `gap` of 0, and a four-state model in which `p13 + p14` or `p31 + p32` is above 100 % (they are two ways out of one draw; `tc` and the kernel accept `60% 30% 80% 20% 50%` without a word, checked on 2026-11-01 with iproute2 6.15, and the chain is then not the one that was written). A key that belongs to another model (`r` in `random`) is refused at its own place.
- **`Loss` is an enum, read by hand.** A derived reader for an enum with a tag collects the mapping first, and an error in a value is then reported at the start of the mapping instead of at the value (seen in the snapshots: `150%` pointed at the `{`). The reader goes through one struct with every key, so errors keep their place, and the checks of missing keys and keys of another model run before it with the line of each key. The schema still has one variant for each model (`oneOf` with a constant `model`), which editors use for completion, and a test compares the required keys of each variant with the table of the reader. This breaks the API of `netscenario-model` (`Loss` was a struct; `LossModel` is gone because the variants say it), hence `feat!`.
- **The order of the stages** in the page of the format is that of `sch_netem.c` (duplicate, loss, corrupt, then rate and delay with reordering); the backend builds it with the impairments (D-054) and the state-to-state test of D-048 holds it.
- **Left for the Kernel backend (D-054, D-055):** the seed also decides duplication, corruption and reordering (one generator per qdisc), so `seeded-loss` must be needed by those too, and `netem.rs` passes the seed only with `loss` today. The argument builder writes the whole state with explicit zeros.
