# D-089: The routes of a node name its own address as the source of what it sends

Accepted (2026-11-05). A fault of D-078 that the first TCP run over a dumbbell showed.

- **Every route of a node has `src <the address of the node on its loopback>`**, in both families. A packet that a program in the node sends over a route has the address of the node as its source, as `from_address` in the result already said, and not the address of the link it leaves by.
- **Why.** The nodes have routes to the addresses of the nodes only (D-078). Without `src` the kernel chose the address of the outgoing interface, and the answer of a TCP server went to a link address that no other node had a route to: the connection hung through any router, until the watchdog ended the run. UDP had never shown it, because nothing answers a UDP stream, except the echo (D-087) on a direct link.
- **What changes for a user.** The source of a packet that crosses a router is the address of the node (`10.200.0.<n>`), which is also what the placeholders (`{client.addr}`) are. A program of your own that binds to the address of a link no longer gets answers from other nodes; it should bind to its node address or not at all.

Alternatives: the agent binds its sockets to the node address (fixes the workloads, not a program of your own); a route to every link subnet on every node (many routes, and the address of a link would then be reachable from anywhere, which D-078 avoided).
