# D-093: Parameters, templates and includes are expanded when a file is read, and the file stays data

Accepted (2026-11-06), for SCN-05. The anchors, aliases and merge keys of YAML are refused since release 0.1 (the file reads the same from top to bottom); this is the designed replacement.

- **Expanded before anything else.** A scenario file is turned into the scenario that it describes by a pass over the YAML tree, before the checks of the contents. What the checks, the hash, `scenario.json` and a replay see is the expanded scenario; nothing after the pass knows that there was a parameter, a template or an include. A file that uses none of them is not touched by the pass, so every file of release 0.2 reads as before.
- **Parameters.** The top-level `params:` declares them: `name: default`, or `name:` without a value for one that must be given. A name is lower case letters, digits and `_`, starting with a letter (no `-`, which is the minus of an expression). A default may use the parameters declared before it (`half: "{rtt / 2}"`). A value is given on the command line (`--param name=value`, repeatable), in Python (`params=`), or by a `with:` of a template; one that is not declared is refused with the declared names. A value must be of the kind of the default (a duration for a duration; `text` takes anything), so `--param rate=50ms` is refused where the default is `10mbit`. The effective values are written back into the expanded scenario as `params:` (text), so they are in its hash and in the result, and a replay of the expanded file expands to itself.
- **Expressions.** A scalar that is, as a whole, `{expression}` (in quotes, because YAML reads an unquoted `{` as a mapping) is replaced by its value. The expression has numbers, quantities as the format writes them (`20ms`, `10mbit`, `1500b`, `2%`), parameter names, `+ - * /`, unary minus and parentheses. No functions, no strings, no comparisons, no loops: a file never computes more than a unit conversion does. The arithmetic is exact (fractions of 128-bit integers), never a float. `+` and `-` need the same kind on both sides; `*` takes a quantity and a number; `/` takes a quantity and a number, or two quantities of the same kind (a number). The result is written in the largest unit that holds it exactly, and a result that is not a whole number of the smallest unit (`40ms / 3` in nanoseconds) is an error that names it, as a literal would be. `{rate}` alone is the value of the parameter as it was written. A text or a boolean can be substituted whole and is refused in arithmetic. A `{...}` inside a longer text (`"link-{n}"`, `"--rate={rate}"`) is replaced by the text of its value. The value of a parameter is used as it is and is never calculated: one that would be an expression when the recorded scenario is read again is refused. `{node.addr}` (a name, a dot, a word) and `{{...}}` are not expressions: they are the placeholders and the escape of the commands of the workloads, which have had their meaning since release 0.2, and stay as they are.
- **Templates and includes** are two ways to name the same thing: a `{ params, content }` definition that is used at a place. `templates:` at the top of a file holds named definitions; a file that is included is one definition (its `params:` and `content:`, and `templates:` of its own for helpers). A place of use is a mapping with `use: name` (a template of this file) or `include: path` (a file), and `with:` for the arguments, and nothing else. It is replaced by the `content`, expanded in a scope of its own: the parameters of the definition and nothing of the caller, so a definition reads the same wherever it is used. The arguments are expressions in the scope of the caller. Where the place is an item of a list and the content is a list, its items are spliced in. So a link, a list of workloads, or the whole `topology` can be a definition.
- **Files** follow D-083 and the path is that of the file that includes, below the directory of the scenario (symbolic links resolved) unless `--allow-outside-files`; at most 4 MiB, read once and then from memory. A definition is used at most 8 levels deep, a cycle is refused with the chain, at most 10,000 places of use and 1,000,000 nodes in all, and the expanded text at most the size of a file.
- **Errors** name the file, line and column where the fault is (inside a template, the line of the template), and then each place of use that led there, from the inside out: `used from scenario.yaml:12:5`. This holds for the checks of the contents and for the refusals of a backend, which find the file and line of the expanded path.
- **The result** has the parameters of the scenario, so a run says which values it was made with.
- **The schema** (`docs/schema/scenario-v0.json`) describes the file as it is written: a string with an expression is accepted wherever a value goes, and a place of use wherever a mapping or a list goes, so an editor does not mark a file that uses them; the reader checks the scenario that results. `Problem` of the model crate carries the file and the places of use (behind a box), which makes it `non_exhaustive`: a break of the API, and the reason for the `!` of the pull request.
- **Not in this decision**: loops or a list of values for a parameter (a matrix is TOP-13 and release 0.5), a file that overrides keys of another (a base scenario), `expect` (ASR-07 has its own), conditionals.

Alternatives: a template engine over the text (Jinja or similar: loops and conditions turn the file into a program, and an error would point into the output nobody wrote); YAML anchors and merge keys (no parameters, and the reader of the file cannot tell what a merge does); expressions in unquoted `${...}` (no quoting in block style, but every flow mapping of this format, `{ delay: ${rtt} }`, needs quotes anyway, and `{...}` is what the plan promised); a deep merge of a base scenario with an overlay (the rules for lists decide what a file means, and every answer surprises someone); floating point arithmetic (`0.1 + 0.2` is not `0.3`, and the format wants whole numbers of the smallest unit).
