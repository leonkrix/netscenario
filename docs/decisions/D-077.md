# D-077: Python gets the reports and the replay as thin layers over the native library, and the properties of the plugin come from the core

Accepted (2026-11-03). Completes the Python layer and the plugin for release 0.2 (PYT-01, PYT-02). D-031 settled how a run is called from Python; D-074 added repetitions; D-075 and D-076 added the replay and the reports to the command line.

- **`report`, `replay` and `junit_properties` have no semantics of their own.** `netscenario.report(directory, format)` is `netscenario report` (the core makes the text, the Python function returns it), `Result.report` and `RunSet.report` are the same for their own directory, and `netscenario.replay(directory)` is `netscenario replay` run on the worker thread of a run, so Ctrl-C, `cancel` and the observer work as for `run` (the run, the set and the replay share one function that starts the thread, watches the interrupts and turns the end into text or an exception). The comparison is made by the core and read into dataclasses (`Replay`, `LostPackets`, `Difference`); nothing is decided in Python (D-002).
- **A replay that differs is returned, not raised** (D-075 made it exit code 1 on the command line, for the same reason): a test that asks "does the replay reproduce?" reads `again.reproduced` and prints `again.verdict` and the packets, which an exception would hide. What cannot be replayed at all (not a run, the directory of a set, a run from before the scenario was recorded, a scenario that is not the one of the result) is a `ValueError` with the reason, before anything runs; `out` being the directory that is replayed is a `ValueError` too. The errors of the run itself are those of `run`.
- **A wrong input of a report is a `ValueError`**: a directory that is not a result, a file that cannot be read, a format that is not `md`, `junit` or `html`. The functions take the format as a `Literal`, so the type checker knows the three.
- **The properties of the pytest plugin come from the core** (`report::run_properties` and `report::set_properties`, which the JUnit report uses for its own test cases and suite): one list, so the plugin and the report cannot differ. The names of release 0.1 are all still there; the list is a superset (duplicates, more delay percentiles, jitter, mean throughput, the longest run of lost packets, the metrics of a program), and the values are **text** now, as they are in the file (the number `0.0` was `0.0` and is `0`; a reader that parses the number is not affected). The suite properties of the report (version, backend, seed, ...) are not given to a test, which has its own.
- **The report section of a test says what happened over time**: the events of the timeline with how late each step was, the time to recover after each event, and how each program of your own ended with the last value of its metrics, besides the numbers of the workloads.
- **The example of a timeline is the scene of the tests of the timeline** (a drop in bandwidth and an outage): the numbers that its test asserts are those that the Kernel backend tests derive and check, with the same bounds, and not new ones picked by eye. The example of a confidence interval is part of the example of the test (D-074), and the example of a program of your own is the echo server (D-072).
- **Tested:** the JSON of a replay read into the types (every verdict, the lists, the machine), the refusals of a replay without a machine, the reports of a result and of a set (the format, the directory, the missing records of the HTML, the wrong format), that the properties of the plugin are those of the report and that nothing is made up, the section of the report with a timeline, and in real namespaces the replay (the same packets, and as the canary another recorded seed that must differ) and the three reports of a real run.

Alternatives: replay as an exception when it differs (a test could not read why); the properties mirrored in Python with a test that compares them with the core (two lists to keep); a `Replay.assert_reproduced()` helper (an `assert` with the verdict says the same); letting `report` write a file (`Path.write_text` does, and the HTML is one string).
