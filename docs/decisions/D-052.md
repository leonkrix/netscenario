# D-052: `duplicate` together with a jitter and a rate is probed on the kernel, not assumed

Accepted (2026-11-01), after the spike S15 (`spikes/s15-duplicate-in-tree.sh`). A note on another emulator said that the kernel refuses every further `netem` on an interface once one has `duplicate`. That is `check_netem_in_tree()`, added to the kernel in 2025 (commit `ec8e0e3d7ade`, against CVE-2025-38553, a soft lockup when a duplicating `netem` shares a tree with other `netem`) and reverted upstream afterwards because it broke configurations that had worked for years (kernel bug 220774, seen on 6.18-rc4). Which kernels have it depends on the distribution. It concerns us in one place: a direction with a jitter and a rate is two `netem` in one tree (D-030), so `duplicate` with both would be refused on a kernel that has the check. One `netem` per direction, which is every other combination, is a tree of one.
- **Measured (S15, seven cases: `duplicate` in a single `netem`, in the root with a child, in the child with a root, added to an existing pair by `change`, a `change` of the child in a tree that has a duplicating root, and a plain `netem` on another interface):** every case was accepted on Debian 13 (kernel 6.12.113, iproute2 6.15), Ubuntu 22.04 (6.8.0-1070-azure) and Ubuntu 24.04 (7.0.0-1017-azure), on the runner images and on this machine; the canary (`duplicate 150%`) is seen as a refusal. So the combination works on the three kernels that the project tests.
- **What that does not show:** kernels between the introduction of the check and its reverts (distribution kernels of the 6.16 to 6.18 time are the candidates). The note is right for those, and the project cannot list them.
- **The decision.** The format accepts `duplicate` with a jitter and a rate (it is a valid thing to ask for, and the Engine backend of release 0.4 has no such rule). The Kernel backend does not trust a version list: `doctor` tries the combination on the machine (a `netem` pair with `duplicate`, in the throwaway namespace of its other probes) and the capability `Duplication` is `Unsupported` with the kernel release in the text where the kernel says no, so that a scenario that needs it is refused before anything is built, with the message of the kernel quoted. Everything else about `duplicate` stays `Exact`. The backend also must not leave a half-built tree when `tc` refuses the second `netem`: it removes the root again (the test of the impairments forces a refusal with a fake `tc`). Alternatives: a kernel version list (it would be wrong for every distribution kernel that backports or reverts); putting all of it into one `netem` when `duplicate` is set (jitter would then act before the rate, which D-030 showed to be a different network); refusing `duplicate` with a jitter and a rate everywhere (loses a combination that works on all tested kernels).
