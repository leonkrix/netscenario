# D-076: A report is made from a result directory and nothing else, in three formats, and the JUnit failures are the ones a result can know

Accepted (2026-11-03). Closes CLI-02, RPT-02, RPT-03, RPT-04 and QA-04 on the Kernel backend. D-043 decided that reports are static, with inline SVG and no JavaScript; this decision settles the rest.

- **A report is a function of a directory.** `netscenario report <dir>` reads `result.json` or `runset.json` and, for the HTML of a run, `series-<id>.jsonl` and `flow-<n>.records`. No clock, no machine, no random numbers: the same directory gives the same bytes, which is what makes snapshots possible. The code is in the core (`netscenario_core::report`), not in the command, so that the Python layer and the plugin can use it later.
- **Output: standard output, or `--out <file>`, for every format** (the maintainer's choice): `report --format md >> "$GITHUB_STEP_SUMMARY"` needs no file. The command exits with 0 whenever the report could be made.
- **One format of each kind for runs and for sets.** A set has no series over time; its HTML draws one dot for each run against the interval of the mean for each headline metric, and its JUnit is one case for each run with the headline metrics as properties of the suite.
- **JUnit: one case for each workload, with the properties of the plugin** (`netscenario.<scenario>.<workload>.sent`, `received`, `lost`, `loss_ratio`, `reordered`, `delay_p50_s`, `delay_p99_s`) and a few more. The plugin writes the first seven; the report is a superset, and the plugin will take the rest where it is changed again.
- **A case fails in two cases** (the maintainer's choice, as "interrupted or program failed"): the run was interrupted (`timing.interrupted_ns`), or the kernel refused packets of the workload and no `down` step of the timeline explains it. A result is written only for a run that went through, so a program with `on-exit: fail` that ended with an error ends the run without a result; the report has no program failure to show and does not invent one (a program that had to be killed after the shutdown signal is in the text and in `ended`, not a failure). A warning about reproducibility is text, not a failure. Failures on numbers come with `expect`.
- **HTML: one file, nothing to fetch.** Inline CSS with variables for the light and the dark scheme, inline SVG with classes, no script, no font, no image, no `xmlns` (an address, in a page that has no use for it). The charts are drawn by a few hundred lines of Rust without a library: lines for the throughput and the delay percentiles, bars for the share of lost packets and for the histogram of the delays, a dot plot for a set. Numbers are written with one decimal and the axes end on 1, 2 or 5 times a power of ten.
- **The lost packets are drawn by the bin in which they were sent**, as the share of the packets of the bin, from the series: the records name only the packets that arrived, so the moment of a lost packet is known only through its slot, which is what the series already uses.
- **Tested:** snapshots (insta) of the Markdown and the JUnit of a run and of a set, and of each of the four drawings of a run and of the plot of a set, made from a fixed run that is built from synthetic records and the library's own series and statistics; the failure rules with a canary for each side; the escaping of names in HTML, XML and Markdown cells; a check that the HTML has no external reference, which is itself checked against pages that have one; the refusals; and a sample report in `docs/sample-report/` that a test makes again.

Alternatives: a chart library (a dependency and a script or a big inline blob; a drawing is a list of marks); a report in the command and not in the core (the Python layer could not use it); PDF (a file for people has HTML); JUnit failures for a loss above a threshold (the result has no thresholds yet and a threshold chosen here would be a bound by eye); drawing the lost packets as marks at their moment (unknown for a packet that did not arrive); standard output only for Markdown and a file for HTML (the formats would behave differently).
