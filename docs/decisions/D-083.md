# D-083: A scenario reads the files it refers to when it is loaded, from its own directory, and the scenario holds what is made of them

Accepted (2026-11-04). Release 0.3 is the first with a file that a scenario refers to (a file of delay samples for a jitter, LNK-02); traces (LMD-03), packet traces (WRK-03) and includes (SCN-05) follow the same rules.

- **The path is relative to the directory of the scenario file.** `netscenario run dir/scenario.yaml` looks next to `dir/scenario.yaml`, not in the working directory. A scenario that is read from a string (Python `Scenario.from_yaml`) has no directory: it gets `base_dir`, and a scenario that refers to a file and has none is refused with that reason.
- **Only files inside that directory.** After links and `..` are resolved a file must lie inside the directory of the scenario file; an absolute path is refused. A scenario from elsewhere must not be able to read `/etc/passwd` or a key in the home directory, and the error must not show the content of a file it refuses. The command line (`--allow-outside-files`) and Python (`allow_outside_files=True`) lift this for a person who knows what the scenario is.
- **At most 16 MiB, regular files only.** The size is checked on the open file and again on what was read, because a file can grow while it is read.
- **The files are read once, when the scenario is loaded, and what is made of them becomes part of the scenario.** The canonical form (and with it `scenario.json` of a run, the hash, a replay, a set of runs) holds the result of reading the file (for a table: the entries, the number of samples, the scale) and the SHA-256 of the file. A recorded scenario runs without the file; a changed file is a changed scenario with another hash; two runs of one scenario cannot differ because the file changed in between. A `sha256` written in the file pins it: the file must have exactly that content.
- **Errors name the place in the scenario** (the path and the line of the `file` key), say what is wrong with the file in a sentence, and never show its content.
- **A scenario that was not given its files does not run.** `run` refuses it with the names of the files; the loaders (`resolve_files` in Rust, `Scenario.load` and `from_yaml(base_dir=...)` in Python, every command of the command line) do the reading.

Alternatives: keep only the path and the hash in the scenario and read the file at the run (a replay and a result passed on to somebody else would need the file at the same place, and a changed file would be a failure of the run and not of the load); any path allowed (a scenario from the internet reads what it likes); the path relative to the working directory (the same scenario file means different things from different places).
