# D-099: The engine's decisions depend on the seed and on the order of the packets, never on the clock; it writes a decision log; "virtual time" means the moments it computes, not a clock for the programs

Accepted (2026-11-12), for BKD-06 and the cells "same seed, same loss pattern" and "same seed, same timing" of the Engine column.

- **A stream for each link, direction and kind of decision.** Loss, jitter, reordering, duplication and corruption each draw from their own stream, seeded from the seed of the run, the link, the direction and the kind (the derivation is written out in `docs/ENGINE.md`). The generator is the one of the agent (SplitMix64 to seed, xoshiro256++ to draw, `ln` made of IEEE operations, D-071), so the same seed gives the same numbers on every machine and in every version. It moves to a place both crates can use. The k-th decision of a stream depends on k and the seed only, so adding a delay or a rate to a link does not shift its losses (a test says so, with a canary that makes one stream draw from another).
- **What is promised.** The same seed and the same sequence of packets give the same decisions: the same packets lost, corrupted, duplicated and reordered, the same jitter samples. With a UDP workload (the packets of a sender are the same each time, D-065) that is the same lost packets on every run, on every machine, whatever the load. For TCP the packets depend on feedback and the run is `statistical` (D-086).
- **What is not promised.** The same moments. The engine runs in real time next to programs that run in real time; a virtual clock for them does not exist. What the engine does have is the moment it computes: from the arrival stamp of a frame (`SO_TIMESTAMPNS`) it computes the moment the frame is due, and it writes both to the **decision log** (the number of the packet, the stamp of arrival, the decision, the due moment, the moment of release). The decisions do not depend on the lateness of the release; the lateness is in the log and in the distribution of the result (ENV-08). The cell "same seed, same timing" is therefore `~`: the due moments are a function of the arrival stamps; the release is as exact as the timer (D-098).
- **The log** is a file of binary records next to the result (`engine-<link>-<direction>.log`), written through a buffer by a thread of its own so that it does not slow the path, with a reader in the core and a fuzz target. A run says in the result how many records it dropped when the buffer was full (never silently incomplete, as the capture, D-047).

Alternatives: one stream for everything (a delay would shift the losses); a clock that the engine controls and that the programs read (impossible for a real kernel stack); no log (the cell would be a claim nobody can check).
